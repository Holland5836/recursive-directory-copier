# recursive-directory-copier\n\nA zero-dependency Node.js (ESM) library that copies a directory tree while preserving POSIX permission bits and copying symlinks as symlinks.\n\n## Usage\n\n```js\nimport { copyTree } from 'recursive-directory-copier';\n\nawait copyTree('./src-dir', './dst-dir');\n```\n\n`copyTree(srcDir, dstDir)` returns a `Promise<void>`. Both arguments are path\nstrings (absolute or relative). The source must be a directory; the destination\nmust either not exist or be a directory.\n\n## Why this exists\n\n`fs.cp` and `fs.copyFile` exist in the standard library, but `fs.cp`'s symlink\nbehaviour is platform-dependent and its permission handling is subject to umask\ninconsistencies. This library makes a single, deliberate set of choices so the\nbehaviour is predictable across Linux and macOS:\n\n- Symlinks are copied as symlinks, including broken ones. We never dereference.\n- File and directory permission bits are reapplied after writing so umask does\n  not interfere.\n- Named pipes, sockets, and device files are rejected with an error rather than\n  silently producing something unexpected.\n\nThe trade-off: we do not preserve atime/mtime, and we do not support Windows.\nBoth would require platform-specific calls that fail silently on common\nfilesystems. Keeping the surface small means the behaviour you get is the\nbehaviour you tested.\n\n## The awkward edge\n\nWhen the destination directory already exists and contains a file that the\nsource also provides, the source file overwrites it. When the destination\ncontains a symlink at a name the source also provides as a symlink, the\ndestination symlink is replaced. We do not recursively delete the destination;\nwe only overwrite the leaf entries we write. If the destination root itself is\na regular file rather than a directory, the copy fails.\n\n## Exports\n\n- `copyTree(srcDir: string, dstDir: string): Promise<void>` — the sole function.\n  A default export of the same `{ copyTree }` object is also provided.\n

## Performance

The window keeps a bounded buffer, so `push` is constant time and memory does not
grow with the length of the stream. `peak` and `trough` are linear in the window
size, which is the trade that keeps `push` cheap.
